# SmartBear 轻量级同行审查落地打分自查表

> **使用说明**：本清单基于 SmartBear 针对 2500 次真实工业级代码审查（Cisco 案例）的实证研究提炼。涵盖审查规模节奏控制、作者提交前导读、人机分工及高发缺陷排查。

---

## 一、 审查规模与节奏控制 (Scope & Pacing)

- [ ] **1. 变更规模在 200~400 行黄金界限内**
  - **判定依据**：本次审查的有效逻辑改动控制在 400 行以内，未将多个无关模块或大型重构混为一谈。
  - **违背代价**：审查者产生认知疲劳，缺陷检出率呈现断崖式下跌，大 PR 沦为形式主义走过场。
- [ ] **2. 审查时长控制在 60 分钟以内**
  - **判定依据**：单次连续审查不超过 60 分钟；超长 PR 已拆解为多批次独立会话。
  - **违背代价**：大脑疲乏导致后半段代码自动忽略隐蔽的边界或并发死锁问题。
- [ ] **3. 审查速率不超过 300~500 行/小时**
  - **判定依据**：审查者留有充分的推导和理解时间，拒绝“5 分钟扫完 500 行”的表面走马观花。
  - **违背代价**：浮于表面的审查错失 80% 的深层架构与逻辑冲突。

---

## 二、 作者自我效应与导读 (Author Self-Review & Tour)

- [ ] **4. 提交前作者已执行逐行自查（Ego Effect 激活）**
  - **判定依据**：作者在发起 PR 前已自己在 Diff 工具中通读过一遍，清理了所有调试 log、临时注释与死代码。
  - **违背代价**：浪费审查者精力指正低级粗心失误，增加沟通内耗。
- [ ] **5. 提供清晰的作者导读与核心高亮**
  - **判定依据**：PR 明确交代了业务背景，指明了最关键的 1~2 个主文件，并对非显而易见的逻辑主动批注了 Why。
  - **违背代价**：审查者缺乏全貌上下文，理解效率降低 30% 以上。

---

## 三、 人机分工与前置流水线 (Automation First)

- [ ] **6. 机器能查的决不浪费人肉精力**
  - **判定依据**：缩进、代码格式（Black/PEP8/ESLint）、无用引用与基础单测已在 CI 流水线中 100% 自动阻断。
  - **违背代价**：人类资深工程师沦为“人肉 Linter”，忽略核心业务死角。
- [ ] **7. 审查聚焦于逻辑、架构与边界**
  - **判定依据**：审查者的所有批注围绕业务数据流完整性、事务安全、边界异常与可维护性展开。
  - **违背代价**：把时间消耗在个人代码风格辩论上，无法产生质量净收益。

---

## 四、 高发缺陷主动挖掘清单 (Defect Mining)

- [ ] **8. 裸取字典/属性与空指针防御**
  - **判定依据**：外部传入或动态解析的数据采用 `.get()` 或具备明确的判空默认值，无裸链式调用。
  - **违背代价**：上游报文字段微调时，服务抛出未捕获的 `KeyError` 或 `AttributeError` 崩溃。
- [ ] **9. 数据库连接与文件资源 100% 安全释放**
  - **判定依据**：所有 DB Connection、Cursor、网络连接与文件读写均由上下文管理器（`with` 语句）或 `try-finally` 托管。
  - **违背代价**：在高频异常流量下连接泄漏，迅速打满数据库连接池导致全站宕机。
- [ ] **10. 循环内部零 I/O 陷阱（N+1 防御）**
  - **判定依据**：循环体内不存在逐行执行 SQL 查询或逐行发起 HTTP 请求的模式，数据已完成批量预查。
  - **违背代价**：数据量从测试环境的几十条上升到现网数万条时，接口延迟暴增数百倍。
- [ ] **11. 异常不被无声吞噬**
  - **判定依据**：禁止使用空的 `except: pass`，所有捕获的异常均有日志记录、监控上报或合理的降级兜底。
  - **违背代价**：底层发生严重数据写入失败，前端依然显示成功，引发幽灵差错。

---

## 五、 缺陷闭环与度量卫生 (Closure & Metrics Hygiene)

- [ ] **12. 必须复核修复 Diff（Verify Fixes）**
  - **判定依据**：审查者在点击 Approve 前，已单独比对作者的 Fix Commit，确认缺陷被根除且未引入次生 Bug。
  - **违背代价**：盲目信任修改，15% 的补丁引发更隐蔽的次生回归缺陷。
- [ ] **13. 附带修复缺陷的回归单元测试**
  - **判定依据**：针对审查中指出的严重逻辑缺陷，作者在同 PR 中补充了复现并锁死该场景的自动化单测。
  - **违背代价**：未来其他开发者重构该模块时，同样的历史 Bug 再次死灰复燃。
- [ ] **14. 严禁将审查缺陷数量用于考评绩效**
  - **判定依据**：审查数据仅用于团队复盘（RCA）和清单迭代，绝不用于开发者绩效考核或打分排名。
  - **违背代价**：古德哈特定律生效，团队陷入刷无意义小批注、掩盖代码问题的政治内卷。
