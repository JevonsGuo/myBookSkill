# 真实缺陷案例 01：短信验证码频控绕过与短信轰炸

| 维度 | 内容说明 |
|:---|:---|
| **缺陷编号** | BUG-SEC-2025-0102 |
| **现象描述** | 登录页虽然前端有 60 秒倒计时，但黑客直接用脚本直接调用 `/api/auth/sendSms` 接口，绕过前端限制，1 秒内发送上百条短信验证码。 |
| **业务危害** | 短信资费消耗严重，接口被用来对他人手机号进行恶意短信轰炸。 |
| **根因分析** | 后端仅依赖前端按钮置灰，服务端 Controller 未做 Redis 手机号限频校验与单 IP 滑动窗口限流。 |

## 防御性用例设计方向
1. **纯后端频控**：绕过前端页面，直接并发调用发送接口，第二笔及后续请求必须返回 HTTP 429 或 `FREQUENCY_LIMIT`。
2. **多维度限频**：测试“单手机号限制”、“单 IP 限制”、“单设备号限制”。
3. **过期后复用**：获取验证码后等待 5 分钟，测试使用过期验证码登录是否被拒绝。
