# OWASP 业务逻辑安全与代码审查落地清单

> **使用说明**：本清单融合了 OWASP Web Security Testing Guide (WSTG-BUSL) 与 OWASP Code Review Guide 的核心业务逻辑防护规范。在审查前后端接口交互、结算对账、资金流转与状态机实现时，逐项核对。

---

## 一、 输入数据与防篡改 (Input Validation & Integrity)

- [ ] **1. 零信任客户端计算结果**
  - **判定依据**：应付金额、折后价、佣金等关键商业数值必须且只能由服务端独立计算，不接收客户端直接传入的计算金额。
  - **违背代价**：用户抓包修改实付金额为 0.01 元或负数，引发重大资金流失。
- [ ] **2. 严格的数值正向区间校验**
  - **判定依据**：所有涉及金额、单价、数量的字段必须强制校验 $> 0$（或退款场景校验 $\le$ 可退上限）。
  - **违背代价**：攻击者传入负数单价反向套现，或退款金额超出订单本金。
- [ ] **3. 权限与对象级别访问控制 (BOLA 防御)**
  - **判定依据**：根据请求中的主键（如 `order_id`, `biz_identifier`）查询数据时，必须校验当前登录人/商户是否有权访问该实体。
  - **违背代价**：水平越权漏洞，攻击者枚举 ID 查看并修改其他商户的结算单据。

---

## 二、 工作流与状态机闭环 (Workflow & State Machine)

- [ ] **4. 状态转移白名单矩阵**
  - **判定依据**：更新单据状态前，显式断言当前持久化状态属于合法源状态集合，禁止任意跳步。
  - **违背代价**：跳过关键审核或对账步骤，未支付订单直接流转至已结算。
- [ ] **5. 终态不可逆与不可篡改**
  - **判定依据**：已处于终态（如 `SETTLED`, `CANCELLED`）的单据，严禁被普通业务接口原地更新。
  - **违背代价**：历史对账数据被覆写，财务报表失真，丢失审计线索。
- [ ] **6. 跨步骤向导服务端独立校验**
  - **判定依据**：多步骤业务流程在每个接口独立校验前序步骤的完成度，不信任前端 UI 的向导状态。
  - **违背代价**：攻击者直接调用最后一步结算接口，绕过前端强制前置检查。

---

## 三、 并发竞态与原子性 (Concurrency & Race Conditions)

- [ ] **7. 消除 TOCTOU 内存时差漏洞**
  - **判定依据**：余额、库存或状态的“检查与更新”通过单条原子 SQL、行级锁（`FOR UPDATE`）或分布式锁保护，不存在检查与更新之间的无锁窗口。
  - **违背代价**：并发请求导致同一笔优惠券被多次使用、库存超卖或账户透支。
- [ ] **8. 锁的粒度与释放安全性**
  - **判定依据**：分布式锁仅锁定业务唯一键（如 `order_id`），设置合理超时时间，释放时原子比对持有者凭据，不在锁内执行耗时外部网络 I/O。
  - **违背代价**：死锁导致服务阻塞，或长事务拖垮数据库连接池。

---

## 四、 幂等性与防重放 (Idempotency & Replay Defense)

- [ ] **9. 数据库物理唯一键防重**
  - **判定依据**：关键结算与回调处理基于 `biz_identifier` 或流水号建立物理唯一索引（Unique Constraint），不仅依赖应用层 `SELECT` 判定。
  - **违背代价**：第三方网络重试或用户双击时，产生多笔重复入账/扣款记录。
- [ ] **10. 幂等响应快照返回**
  - **判定依据**：重复请求命中幂等时，返回与首次成功执行一致的响应快照，而不是直接抛出 500 异常。
  - **违背代价**：第三方回调平台误判失败，持续重发消息造成重试风暴。

---

## 五、 金融计算与安全失败 (Financial Rules & Fail-Safe)

- [ ] **11. 绝对禁用二进制浮点数进行金额运算**
  - **判定依据**：代码中金额必须使用 `decimal.Decimal` 或整数“分”，严禁使用 `float` / `double` 进行加减乘除。
  - **违背代价**：`0.1 + 0.2` 精度失真导致平账校验失败，系统每日产生大量虚假差错告警。
- [ ] **12. 显式指定四舍五入模式与尾项平账**
  - **判定依据**：金额计算显式声明 `ROUND_HALF_UP` 等截断策略，多方费用分摊时采用尾项平账（差额倒挤法）确保总和守恒。
  - **违背代价**：长期分摊产生累计 1 分钱差额，财务月结账目不平。
- [ ] **13. 默认安全失败（Fail-Closed 原则）**
  - **判定依据**：未捕获异常或第三方超时，系统严格拒绝操作并回滚事务，绝不允许异常时默认判定为对账成功。
  - **违背代价**：系统在网络故障时把未核对的单据静默判定为已平账。
- [ ] **14. 核心事务原子闭环**
  - **判定依据**：资金扣划、账单变更与流水插入处于同一数据库事务中，失败时统一回滚。
  - **违背代价**：网络异常时单边入账，留下悬挂的孤儿资金记录。
- [ ] **15. 敏感商业数据脱敏与日志保护**
  - **判定依据**：日志中严禁明文打印用户银行卡号、完整密码、私钥等核心凭据。
  - **违背代价**：日志泄露引发严重的数据合规与安全法律风险。
