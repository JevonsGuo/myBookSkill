# 真实缺陷案例 03：并发弱网重试导致账户余额扣成负数 (双花)

| 维度 | 内容说明 |
|:---|:---|
| **缺陷编号** | BUG-PAY-2025-0722 |
| **现象描述** | 账户余额仅有 100 元，用户在移动端弱网环境下同时发起两笔 100 元的扣款请求，系统两笔均扣款成功，账户余额变为 -100 元。 |
| **业务危害** | 平台出现直接资金资损，黑客可恶意套现。 |
| **根因分析** | 典型的 TOCTOU（Time-of-Check to Time-of-Use）并发竞态。代码先 `SELECT balance FROM account`，判断 100 >= 100 通过，再执行 `UPDATE account SET balance = balance - 100`。由于并发时差，两个事务读取到了相同的前置余额。 |

## 防御性用例设计方向
1. **并发竞态压测**：使用并发请求同时提交扣款，断言数据库必须借助原子单条更新 `WHERE balance >= 100` 或悲观锁，确保仅有一笔成功，余额恒大于等于 0。
2. **唯一支付单号幂等**：同一笔订单多次提交支付，断言第二笔直接返回已支付中或重复请求错误。
