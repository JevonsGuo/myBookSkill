# 真实缺陷案例 02：Token 失效后下游微服务未拦截

| 维度 | 内容说明 |
|:---|:---|
| **缺陷编号** | BUG-AUTH-2025-0418 |
| **现象描述** | 用户点击登出退出登录后，使用此前持有的旧 JWT Token 依然可以成功调用查询个人资料与下单接口。 |
| **业务危害** | 公用电脑或设备丢失后，历史会话未被销毁，造成敏感数据泄露与盗刷。 |
| **根因分析** | JWT 为无状态验证，登出时网关仅删除了前端 Cookie，服务端没有在 Redis 黑名单中记录已登出的 JTI（Token ID）。 |

## 防御性用例设计方向
1. **登出立即失效**：点击退出登录后，立即以旧 Token 请求受保护资源，断言必须返回 401 Unauthorized。
2. **修改密码会话踢出**：修改密码后，断言所有历史已签发设备会话全部失效，必须重新认证。
